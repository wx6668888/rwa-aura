# RWA Protocol 用户端整体逻辑

本文档从**用户视角**梳理：用户进入站点后能看到什么、能做什么、数据从哪来、和链/后端的关系。

---

## 一、用户入口与导航

- **首页** `/`：品牌介绍、协议亮点、数据概览（TVL/APY 等）、如何参与。
- **导航**（顶部/底部）：连接钱包后，可按模块进入：
  - **我的资产**：仪表板、质押、提现
  - **交易市场**：行情、兑换、紧急提取
  - **抽奖**：幸运抽奖
  - **数据分析**：协议数据、收益计算器
  - **节点与推荐**：节点等级与推荐网络
  - **更多**：治理、安全、公告、帮助、关于等

**链与合约**：用户连接钱包后，前端根据当前连接的链（BSC 主网 / BSC 测试网 / Hardhat 本地）从 `addresses.ts` 取对应合约地址，所有读链、发交易都基于该链。

---

## 二、核心流程 1：质押（Stake）

**页面**：`/stake`（质押页）

**用户能做什么**：

1. **选择质押方式**：**USDT 质押** 或 **RWA 质押**（默认推荐 RWA）。
2. **输入金额**：前端会校验余额、最低 100 USDT 等值。
3. **（首次）填写推荐人**：可选；一旦链上写入则不可改。
4. **选择锁仓期限**：灵活 / 30 / 90 / 180 / 365 天，锁仓越长收益倍数越高（如 0.8% 基础日息 × 倍数）。
5. **授权 + 质押**：先对合约 Approve，再调用合约的 `stake`（USDT）或 `stakeRWA`（RWA）。

**链上逻辑（简要）**：

- **USDT 质押**：用户 USDT 转入合约 → 50% 进 Treasury、50% 进社区池；合约按日发 RWA 静态收益，并参与推荐/节点动态奖励。
- **RWA 质押**：用户 RWA 转入合约 → 同样 50/50 分配；合约发 stRWA 凭证、按日计 RWA 收益；可选锁仓，锁仓部分到期后可解锁取回本金。
- 推荐人一经写入链上即永久绑定；节点等级由后端根据团队业绩等计算后写回链上。

**用户看到的结果**：交易成功后，仪表板/资产数据会更新（总质押、待领取收益、节点等级等）。

---

## 三、核心流程 2：提现（Withdraw）

**页面**：`/withdraw`（提现页）

**用户能做什么**（四个卡片对应四类操作）：

1. **RWA 提现**（`RwaWithdrawCard`）  
   - 仅提「已结算的 RWA 收益」；本金在下方「本金提取」区按类型（灵活 USDT/RWA、到期锁仓 USDT/RWA）单独操作。  
   - 收益提现有 24 小时冷却与 8% 立即到账手续费（3% 回购/销毁、3% Treasury、2% 社区池）；stRWA 模式 0% 手续费、120% 锁 30 天。

2. **stRWA 解锁**（`StRWAUnlockCard`）  
   - 对**已锁仓到期**的 RWA 本金发起解锁，把 stRWA 换回 RWA 取回。

3. **USDT 奖励领取**（`UsdtRewardsCard`）  
   - 领取链上记录的「动态奖励」（推荐/节点等）为 USDT。

4. **投资份额 / 国库相关**（`InvestmentSharesCard`）  
   - 查看或操作与 Treasury 投资份额相关的逻辑（若合约开放）。

**数据来源**：可提金额、冷却、手续费等来自合约只读（如 `getUserStakeInfo`、RWA 质押视图）；前端只做展示与调用提现/解锁/领取接口。

---

## 四、核心流程 3：交易市场（行情 + 兑换 + 紧急）

- **行情** `/market`：RWA 价格、K 线/图表、近期成交等（多为前端/后端聚合展示，不一定每条都上链）。
- **兑换** `/swap`：  
  - **USDT → RWA**：通过 Swap 合约用 USDT 买 RWA。  
  - **stRWA ↔ RWA**：通过对应合约把 stRWA 换成 RWA 或反向（视合约开放情况）。
- **紧急提取** `/emergency`：在特殊情况下（如协议风险提示）用户可发起「紧急提取」，通常只能取回部分本金（如 50%），需仔细阅读页内说明再操作。

---

## 五、节点与推荐（/nodes）

**页面**：`/nodes`（节点等级与推荐网络）

**用户能看到/能做**：

- **当前节点等级**：L1–L9，由链上 + 后端计算的团队业绩/个人质押等决定；前端从合约读 `nodeLevel` 并展示对应名称与升级要求。
- **推荐质量考核**：有效直推率、团队平均质押、质量分等（数据可来自后端或链上汇总）。
- **奖励比例表**：各等级对应的奖励比例与项目分红权重。
- **推荐网络**：我的推荐链接、下级列表/树状图（数据来自链上事件或后端索引）。

**逻辑要点**：推荐人链上绑定后不可改；节点等级由后端按规则计算后，通过合约的 `updateNodeLevel` 写回链上，前端只读展示。

---

## 六、抽奖（/lucky）

**页面**：`/lucky`（幸运抽奖）

**用户能做什么**：

- 选择**周奖池**或**月奖池**。
- 使用 RWA/USDT 等**购买抽奖券**（调用抽奖合约）。
- 查看**我的票据**、**奖池金额**、**中奖概率说明**、**开奖历史**与**公平性说明**。

**数据来源**：奖池、票据数量、开奖结果等来自抽奖合约只读或事件；前端负责展示与发起购票/领奖等交易。

---

## 七、数据分析与计算器

- **协议数据** `/analytics`：TVL、质押人数、协议收入等大盘数据（多为后端汇总或链上聚合）。
- **收益计算器** `/calculator`：用户输入质押金额、锁仓期限、节点等级、推荐人数等，前端按协议规则估算**静态收益 + 推荐/节点动态收益**，仅作参考，不做链上读写。

---

## 八、其他页面（治理、安全、公告、帮助、关于）

- **治理** `/governance`：协议参数、资金状况、Timelock 队列、链上活动等只读展示。
- **安全** `/security`：审计报告、安全说明等静态或配置内容。
- **公告** `/announcements`：列表 + 详情，通常来自 CMS 或静态配置。
- **帮助** `/help`、**关于** `/about`：说明与品牌信息。

---

## 九、用户端数据流小结

| 数据类型           | 来源                     | 说明                         |
|--------------------|--------------------------|------------------------------|
| 钱包地址、链 ID   | 钱包（如 MetaMask）      | 决定用哪条链、哪套合约地址   |
| 余额、授权、质押  | 链上只读 / 合约事件      | USDT、RWA、stRWA、质押视图   |
| 推荐人、节点等级  | 链上（合约存储）         | 后端会写回节点等级           |
| 可提金额、冷却    | 链上只读                 | 提现页展示与按钮状态         |
| 推荐网络、下级    | 链上事件或后端索引       | 节点页树状图与列表           |
| 行情、大盘统计    | 后端/第三方 API 或链上   | 市场页、仪表板部分统计       |
| 收益估算          | 前端按规则计算           | 计算器仅作估算，非链上数据   |

整体上：**用户端 = 连接钱包 → 选链 → 读链/读后端 → 发起授权与合约调用（质押、提现、兑换、抽奖等）→ 结果再通过读链/读后端展示**。正式部署时只需切到主网并配置对应合约地址与环境变量即可。
