# rwa.lat — C 端内容与文案方案（基于当前代码能力）

> **依据**：`frontend/app` 路由、`frontend/lib/i18n.ts`、`contracts/StakingContract.sol` 中与用户相关的机制（质押、提现费用结构、锁仓、推荐、节点等级等）。  
> **注意**：下文「收益/比例」须与**实际上线参数及法务意见**最终核对；对外文案避免「保本、无风险、固定收益」等表述，建议统一用「按合约与规则计算」「以链上为准」等措辞。

---

## 一、为什么要做分类文案

`rwa.lat` 面向 C 端时，用户路径分散在多个页面，与代码一一对应：

| 路由（代码） | C 端心智 |
|-------------|----------|
| `/` 首页 | 我是谁、能做什么、为什么选 BSC/钱包 |
| `/stake` | USDT / RWA 质押、锁仓、gasless |
| `/swap` | USDT↔RWA（协议/Pancake 等以实际 UI 为准） |
| `/withdraw` | 多面板：快提、收益、本金、推荐奖、分红、stRWA |
| `/dashboard` | 资产、团队、活动流水 |
| `/node/network`、`/referral-network` | 推荐关系、团队数据 |
| `/nodes`、`/nodeLevels`（i18n） | 节点等级与升级条件 |
| `/market` | 行情/价格展示 |
| `/knowledge`、`/help` | 教育内容 |
| `/security`、`/privacy`、`/terms` | 信任与合规 |
| `/emergency` | 紧急情况说明（若有） |
| `/dividend`、`/announcements` | 分红与公告 |

文案应 **按模块撰写**，避免首页堆全长规则；细则链到帮助中心或弹层。

---

## 二、文案大类（建议优先级）

### A. 品牌与域名认知（全站顶层）

**要写什么**

- **一句话定位**：RWA 协议 + 链上质押/链上可查（不夸大「持牌」「兜底」除非有据）。
- **域名 rwa.lat 说明**：简短解释 `.lat` 与品牌记忆点（可选：Latin America / 延展叙事需与法务一致）。
- **链与钱包**：BSC 主网；需 BNB（gas）或部分操作为 gasless（与 `relayer` 一致）。
- **三键行动**：质押 / 兑换 / 仪表盘（与导航一致）。

**参考句式（需润色）**

> 「在 rwa.lat 用钱包连接 BSC，质押 USDT 或 RWA，收益与记录链上可查。」

---

### B. 首页 Hero 与价值区块（对应 `hero-section`、统计数据）

**要写什么**

- **副标 / Overline**：真实资产叙事 + Web3（与现有 `hero.overline`、`hero.real` 语系一致）。
- **轮转标签**：与产品钩子一致（收益可视化、链上透明、多语言等）。
- **社会证明**：若上链数据来自 API，需注明「数据来源：链上/统计接口」，避免虚构 TVL。

---

### C. 质押 `/stake`（核心转化）

**要写什么（与 i18n `stakeMode*`、锁仓文案一致）**

- **USDT 质押**与 **RWA 质押**并列说明：各自锁仓选项（灵活 / 30 / 90 / 180 / 365 天——以合约为准）。
- **收益率表述**：示例代码中有「静态日化」「节点等级加成」等，对外建议写「规则见节点说明」「以合约与当时参数为准」。
- **Gasless**：「部分场景由协议代付 Gas，仍需连接钱包签名」——避免说「完全不要 Gas」。
- **推荐人**：首次质押绑定推荐关系（与链上 `_bindUnifiedReferrer` 逻辑一致）；说明不可随意改（若产品如此）。
- **风险**：代币价格波动、智能合约风险、网络拥堵。

**分类子文案**

1. 首屏：三步（连接钱包 → 选种类与期限 → 签名确认）  
2. FAQ：最低额、到账时间、锁仓能否提前（以合约为准）  
3. 与 Swap 的引导：若仍有「先买 RWA 再质押」业务规则，保留简短一句 + 链到 `/swap`

---

### D. 兑换 `/swap`

**要写什么**

- USDT↔RWA 路径说明（协议内 swap vs DEX ——按实际 `swap-card` / `protocol-swap-engine` 能力写）。
- **滑点、授权（Approve）**：用户需理解首次授权。
- **价格与冲击**：「显示价格来源于报价接口/池子，成交以链上为准」。

---

### E. 提现 `/withdraw`（多资产心智）

**代码侧有多种面板**（`panel-quick-withdraw`、`panel-principal`、`panel-rwa-yield`、`panel-referral`、`panel-dividend`、`panel-strwa` 等），文案需 **分卡片**：

| 模块 | C 端要写清 |
|------|------------|
| 一键提取 | 聚合哪些资产、顺序、是否多笔交易 |
| 本金（USDT/RWA） | 锁仓到期、手续费（合约 `WITHDRAWAL_FEE` 等等）、冷却（若有） |
| RWA 收益 | 与动态收益/静态收益表述一致 |
| 推荐奖励 | 周期（如每周）、最低提现额（代码里有 100 USDT 提示） |
| 项目分红 | 结算周期（如每月）、币种 USDT |
| stRWA | 与锁仓到期、mints/burns 相关说明 |

**费用透明（来自合约注释，对外需换算成用户语言）**

- 提现涉及费率和分配（手续费、回购、国库、池子等）——应用 **一张表** 或「详见帮助中心」链接，避免首页冗长。

---

### F. 仪表盘 `/dashboard`

**要写什么**

- **我的资产**：总质押、stRWA、团队总质押、留存等指标定义（与后端 `/api/data` 口径一致时可写「统计口径说明」小字）。
- **资金流水**：链上可查、浏览器链接。
- **刷新行为**：交易成功后数据延迟时可提示「等待区块确认」。

---

### G. 推荐与节点 `/referral-network`、`/node/network`、`/nodes`

**要写什么**

- **直推 / 团队**：与 `referral_bindings`、团队聚合逻辑一致；说明「数据来源于链上与索引」。
- **节点等级 L1–L9**：与 `i18n` `nodeLevels.l*` 中的条件（个人质押、团队体量）一致；**数字必须与实际合约/配置同步**，否则易纠纷。
- **静态 / 动态 / 分红**：用 `yieldExplain1–4` 的结构化说明，避免承诺「每日必到」。

---

### H. 安全与信任 `/security`

**要写什么**

- 合约开源/验证链接（BSCScan）。
- 权限模型：Owner、Backend、国库、迁移开关（简要，不过度技术）。
- 用户自保：私钥、钓鱼、假域名（强调 **唯一官网 rwa.lat**）。
- **免责声明**：非银行、非存款；数字资产波动与合约风险。

---

### I. 法律与隐私 `/terms`、`/privacy`

**要写什么**

- 服务条款：适用法域、用户义务、免责、争议解决（需法务起草）。
- 隐私：连接钱包不收集 KYC 时的数据说明；若接统计（Vercel/CF）需披露。

---

### J. 帮助中心 `/help`、`/knowledge`

**要写什么**

- **按任务分类**：买币、连钱包、质押、赎回、推荐、找不到收益。
- **链上教学**：如何在 BSCScan 查自己的交易。
- **常见问题**：Gas 不足、签名校验失败、切换网络。

---

### K. 公告与迁移（换域名 / 换合约期间）

**要写什么**

- **rwa.lat 上线公告**：旧域名跳转说明、是否更换合约地址、用户无需换钱包。
- **维护窗口**：若迁移中暂停服务，写清时间与恢复条件。

---

### L. SEO 与多语言

**要写什么**

- **中/英至少**：与 `localeOptions` 一致的关键页 `title` / `description`。
- **品牌词**：RWA Protocol、rwa.lat、BSC Staking 等（按市场策略定）。
- **结构化数据**：谨慎，避免虚假评分。

---

## 三、落地执行建议（与你现有工程衔接）

1. **主文案入 `frontend/lib/i18n.ts`**（`zh` 与 `en` 先完整，其它语言可后补），避免硬编码在组件里。  
2. **长文**（条款、安全白皮书级别）可放 `frontend/app/terms/page.tsx` 或 `knowledge` MD/JSON 数据源（若已有 `knowledge-content-*`）。  
3. **换域名**：`NEXT_PUBLIC_APP_URL=https://rwa.lat`、WalletConnect metadata、`robots.txt` / `sitemap`、Nginx 301 从旧域过来。  
4. **上线前检查**：所有对外数字与 `_constants` / 合约参数 **对表一次**。
